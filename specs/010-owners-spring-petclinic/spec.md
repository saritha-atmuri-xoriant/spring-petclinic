# Feature Specification: Owners for Spring Petclinic

**Feature Branch**: `010-owners-spring-petclinic`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "owners for spring-petclinic"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Find Owners by Last Name (Priority: P1)

Given an owner with the last name "Franklin" exists, When a user searches for owners with the last name "Franklin", Then the system redirects to the owner's details page.

**Why this priority**: This is a core functionality for managing pet owners and is essential for basic system operation.

**Independent Test**: Can be fully tested by searching for an existing owner's last name and verifying redirection to their detail page.

**Acceptance Scenarios**:

1. **Given** an owner with the last name "Franklin" exists in the system, **When** a user navigates to the owner search page and enters "Franklin" in the last name field, **Then** the system redirects to the owner's detail page.

---

### User Story 2 - Find Owners with Partial Last Name Match (Priority: P2)

Given multiple owners whose last names start with "Frank" exist, When a user searches for owners with the last name "Frank", Then a list of owners is displayed.

**Why this priority**: This provides flexibility for users who may not recall the exact last name, improving usability.

**Independent Test**: Can be fully tested by searching for a partial last name that matches multiple owners and verifying a list is displayed.

**Acceptance Scenarios**:

1. **Given** multiple owners exist with last names starting with "Frank" (e.g., "Franklin", "Frankenstein"), **When** a user searches for owners with the last name "Frank", **Then** a list of all matching owners is displayed.

---

### User Story 3 - Handle Whitespace in Last Name Search (Priority: P3)

Given an owner with the last name "Franklin" exists, When a user searches for owners with the last name " Franklin " (with leading/trailing spaces), Then the system redirects to the owner's details page.

**Why this priority**: This enhances user experience by making the search more forgiving of minor input errors.

**Independent Test**: Can be fully tested by searching for an existing owner's last name with leading/trailing spaces and verifying redirection.

**Acceptance Scenarios**:

1. **Given** an owner with the last name "Franklin" exists, **When** a user searches for owners with the last name " Franklin " (with leading and trailing spaces), **Then** the system redirects to the owner's detail page.

---

### User Story 4 - Create New Owner (Priority: P1)

Given a user has the necessary permissions, When a user navigates to the owner creation form and provides valid owner details (first name, last name, address, city, telephone), Then a new owner is successfully created and added to the system.

**Why this priority**: Core functionality for adding new clients to the clinic.

**Independent Test**: Can be fully tested by filling out the owner creation form with valid data and verifying the owner is added.

**Acceptance Scenarios**:

1. **Given** the owner creation form is accessible, **When** a user enters valid data for first name, last name, address, city, and a 10-digit telephone number, **Then** the owner is created and visible in the owner list.

---

### User Story 5 - Add Pet to Owner (Priority: P1)

Given an existing owner, When a user navigates to the owner's detail page and initiates the process to add a new pet, providing a pet name and type, Then the new pet is successfully associated with the owner.

**Why this priority**: Essential for managing the pets associated with each owner.

**Independent Test**: Can be fully tested by selecting an owner, adding a pet with valid details, and verifying the pet appears on the owner's detail page.

**Acceptance Scenarios**:

1. **Given** an existing owner "John Doe" exists, **When** a user navigates to John Doe's detail page, selects "Add Pet", and enters "Buddy" as the pet name and "Dog" as the pet type, **Then** "Buddy" is listed as a pet belonging to John Doe.

---

### User Story 6 - Update Pet Information (Priority: P2)

Given an existing pet associated with an owner, When a user navigates to the pet's details and updates its name or birth date, Then the pet's information is successfully updated.

**Why this priority**: Allows for correction of errors or updating of pet details as needed.

**Independent Test**: Can be fully tested by selecting a pet, changing its name or birth date, and verifying the update.

**Acceptance Scenarios**:

1. **Given** a pet named "Buddy" exists for owner "John Doe", **When** a user navigates to Buddy's details and changes the name to "Buddy Jr.", **Then** the pet's name is updated to "Buddy Jr.".

---

### User Story 7 - Record a Visit for a Pet (Priority: P1)

Given an existing pet, When a user navigates to the pet's detail page and initiates the process to record a visit, providing a date and description, Then a new visit record is successfully created for that pet.

**Why this priority**: Core functionality for tracking pet health history.

**Independent Test**: Can be fully tested by selecting a pet, adding a visit with a date and description, and verifying the visit is recorded.

**Acceptance Scenarios**:

1. **Given** a pet named "Buddy" exists for owner "John Doe", **When** a user navigates to Buddy's detail page, selects "Add Visit", and enters today's date and "Routine check-up" as the description, **Then** a visit record for "Routine check-up" on today's date is associated with Buddy.

---

### Edge Cases

- **Blank Address**: Owner creation/update with a blank address will result in a validation error.
- **Blank City**: Owner creation/update with a blank city will result in a validation error.
- **Invalid Telephone Format**: Owner creation/update with a telephone number not matching the 10-digit pattern will result in a validation error.
- **Non-existent Owner ID**: Attempting to access or modify an owner with an ID that does not exist will result in an `IllegalArgumentException` indicating owner not found.
- **Blank Pet Name**: Pet creation/update with a blank name will result in a validation error.
- **Missing Pet Type**: Pet creation with a missing pet type will result in a validation error.
- **Invalid Pet Birth Date**: Pet creation/update with a null birth date will result in a validation error.
- **Duplicate Pet Name for Same Owner**: Attempting to add a pet with a name that already exists for the same owner will result in a validation error.
- **Invalid Visit Date**: Visit creation with a date that is not after the current date will result in a validation error.
- **Non-existent Pet ID for Owner**: Attempting to create a visit for a pet that does not exist for a given owner will result in an `IllegalArgumentException` indicating pet not found.
- **Owner Not Found During Find**: Searching for owners with a last name that yields no results will result in a validation error indicating "not found".
- **Triggering Generic Exception**: Navigating to the "/oups" endpoint will throw a `RuntimeException`, showcasing exception handling.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow the creation of new owners with first name, last name, address, city, and telephone.
- **FR-002**: System MUST allow searching for owners by last name, supporting exact matches and partial matches.
- **FR-003**: System MUST allow the creation of new pets for an owner, including pet name and type.
- **FR-004**: System MUST allow updating an existing pet's name and birth date.
- **FR-005**: System MUST allow recording a visit for a pet, including date and description.
- **FR-006**: System MUST validate owner information during creation or update, enforcing non-blank fields for first name, last name, address, and city, and a 10-digit format for telephone.
- **FR-007**: System MUST validate pet information during creation or update, enforcing non-blank pet names and valid pet types.
- **FR-008**: System MUST prevent duplicate pet names for the same owner.
- **FR-009**: System MUST validate visit information during creation, enforcing a valid date and non-blank description.
- **FR-010**: System MUST handle cases where an owner or pet ID does not exist, providing appropriate error messages.
- **FR-011**: System MUST display a list of pets associated with an owner on the owner's detail page.
- **FR-012**: System MUST display a list of visits associated with a pet on the pet's detail page.
- **FR-013**: System MUST handle leading/trailing whitespace in owner last name searches.

### Key Entities *(include if feature involves data)*

- **Owner**: Represents a pet owner. Key attributes include first name, last name, address, city, and telephone number. An owner can have multiple pets.
- **Pet**: Represents a pet belonging to an owner. Key attributes include name, birth date, and pet type. A pet belongs to one owner and can have multiple visits.
- **PetType**: Represents the type of a pet (e.g., Dog, Cat). Key attribute is the name of the pet type.
- **Visit**: Represents a visit to the clinic for a pet. Key attributes include date and description. A visit is associated with one pet.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can successfully create a new owner in under 1 minute.
- **SC-002**: Owner searches by last name return results within 2 seconds.
- **SC-003**: Users can add a new pet to an owner in under 45 seconds.
- **SC-004**: 95% of pet and owner data entries pass validation checks on the first attempt.
- **SC-005**: Users can record a visit for a pet in under 30 seconds.

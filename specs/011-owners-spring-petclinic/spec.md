# Feature Specification: Owner Management

**Feature Branch**: `011-owners-spring-petclinic`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "owners for spring-petclinic"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Find Owners by Last Name (Priority: P1)

Given an owner with the last name "Franklin" exists, When a user searches for owners with the last name "Franklin", Then the system displays the owner's detail page.

**Why this priority**: This is a core functionality for managing pet clinic data, allowing staff to quickly access owner information.

**Independent Test**: Can be fully tested by navigating to the owner search page, entering "Franklin" in the last name field, and verifying that the correct owner's details are displayed.

**Acceptance Scenarios**:

1. **Given** the system has owners with last names "Franklin", "Davis", and "Smith", **When** a user searches for owners with the last name "Franklin", **Then** the system displays the details for the owner named "Franklin".
2. **Given** the system has owners with last names "Franklin", "Davis", and "Smith", **When** a user searches for owners with the last name "Jones" (which does not exist), **Then** the system displays a "No owners found" message.

---

### User Story 2 - Create a New Owner (Priority: P1)

Given a user is on the new owner form, When they submit a valid owner form with all required fields, Then the owner is created and the user is redirected to the owner's detail page.

**Why this priority**: This is essential for onboarding new clients and their pets into the system.

**Independent Test**: Can be fully tested by navigating to the new owner form, filling in all valid details, submitting the form, and verifying that the new owner's details are displayed on their respective page.

**Acceptance Scenarios**:

1. **Given** a user is on the new owner form, **When** they submit a valid owner form with first name, last name, address, city, and telephone, **Then** the owner is created and the user is redirected to the newly created owner's detail page.

---

### User Story 3 - Handle Invalid Owner Creation (Priority: P2)

Given a user is on the new owner form, When they submit an invalid owner form (e.g., missing required fields, invalid phone number), Then the system displays an error message indicating the validation failures and returns the user to the owner creation form with the entered data preserved.

**Why this priority**: Ensures data integrity and provides clear feedback to the user when data is incorrect.

**Independent Test**: Can be fully tested by navigating to the new owner form, submitting it with invalid data, and verifying that error messages are displayed and the entered data remains in the form fields.

**Acceptance Scenarios**:

1. **Given** a user is on the new owner form, **When** they submit the form with a blank address, **Then** the system displays a validation error for the address field and the form remains visible with the previously entered data.
2. **Given** a user is on the new owner form, **When** they submit the form with a telephone number that is not 10 digits, **Then** the system displays a validation error for the telephone field and the form remains visible with the previously entered data.

---

### User Story 4 - Update an Existing Owner (Priority: P2)

Given a user is viewing an existing owner's detail page, When they choose to edit the owner's information and submit valid updated details, Then the owner's information is updated and the detail page reflects the changes.

**Why this priority**: Allows for correction of errors or updating of client information as it changes.

**Independent Test**: Can be fully tested by navigating to an owner's detail page, initiating an edit, changing a field (e.g., city), submitting the changes, and verifying that the updated information is displayed.

**Acceptance Scenarios**:

1. **Given** an owner "John Doe" exists with city "New York", **When** the user edits the owner and changes the city to "Los Angeles", **Then** the owner's detail page now shows "Los Angeles" as the city.

---

### User Story 5 - Add a New Pet to an Existing Owner (Priority: P1)

Given a user is viewing an owner's detail page, When they choose to add a new pet and submit valid pet details (name, birth date, type), Then the new pet is associated with the owner and displayed on the owner's detail page.

**Why this priority**: Core functionality for managing a client's pets within the clinic system.

**Independent Test**: Can be fully tested by navigating to an owner's detail page, initiating the add pet process, filling in valid pet details, submitting, and verifying the new pet appears on the owner's page.

**Acceptance Scenarios**:

1. **Given** owner "Jane Smith" exists, **When** the user adds a new pet named "Buddy" of type "Dog" with a birth date, **Then** "Buddy" is listed as one of Jane Smith's pets.

---

### User Story 6 - Update an Existing Pet's Information (Priority: P2)

Given a user is viewing an owner's detail page with associated pets, When they choose to edit a specific pet and submit valid updated details (e.g., name, birth date), Then the pet's information is updated and reflected on the owner's detail page.

**Why this priority**: Allows for correction of pet information.

**Independent Test**: Can be fully tested by navigating to an owner's page, selecting a pet to edit, changing its name, submitting, and verifying the updated name is displayed.

**Acceptance Scenarios**:

1. **Given** owner "Jane Smith" has a pet named "Buddy" (Dog), **When** the user edits "Buddy" and changes its name to "Buddy Jr.", **Then** the pet is now listed as "Buddy Jr." on Jane Smith's page.

---

### Edge Cases

- **Blank Address**: Owner creation/update with a blank address → validation error.
- **Blank City**: Owner creation/update with a blank city → validation error.
- **Invalid Telephone Format**: Owner creation/update with a telephone number not matching the 10-digit pattern → validation error.
- **Non-existent Owner ID**: Attempting to access or modify an owner with an ID that does not exist → `IllegalArgumentException` indicating owner not found.
- **Blank Pet Name**: Pet creation/update with a blank name → validation error.
- **Missing Pet Type**: Pet creation with a missing pet type → validation error.
- **Invalid Pet Birth Date**: Pet creation/update with a null birth date → validation error.
- **Duplicate Pet Name for Same Owner**: Attempting to save a pet with a name that already exists for the same owner → validation error.
- **Invalid Visit Date**: Visit creation with a date that is not in the future → validation error.
- **Non-existent Pet ID for Owner**: Attempting to create a visit for a pet ID that does not exist for a given owner → `IllegalArgumentException` indicating pet not found.
- **Triggering Generic Exception**: Navigating to the "/oups" endpoint → `RuntimeException` is thrown, indicating an expected exception scenario.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST allow the creation of a new pet for an existing owner.
- **FR-002**: System MUST allow updating an existing pet's name.
- **FR-003**: System SHOULD validate pet information during creation or update.
- **FR-004**: System SHOULD allow finding owners by last name.
- **FR-005**: System SHOULD allow retrieving a specific owner by ID, including their pets.
- **FR-006**: System MUST allow creating a new owner.
- **FR-007**: System MUST allow updating an existing owner's details (address, city, telephone).
- **FR-008**: System MUST validate owner details upon creation and update.
- **FR-009**: System MUST allow viewing an owner's details, including all their associated pets.
- **FR-010**: System MUST allow viewing a specific pet's details.
- **FR-011**: System MUST prevent duplicate pet names for the same owner.

### Key Entities *(include if feature involves data)*

- **Owner**: Represents a pet owner. Attributes include first name, last name, address, city, and telephone number. An owner can have multiple pets.
- **Pet**: Represents a pet belonging to an owner. Attributes include name, birth date, and type. A pet belongs to one owner and can have multiple visits.
- **PetType**: Represents the type of pet (e.g., Dog, Cat). Attributes include name.
- **Visit**: Represents a visit for a pet. Attributes include date and description. A visit is associated with one pet.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Users can find an owner by last name in under 3 seconds.
- **SC-002**: New owner creation is completed successfully in under 5 seconds for valid data.
- **SC-003**: Validation errors for owner creation/update are displayed to the user within 1 second of submission.
- **SC-004**: Adding a new pet to an owner is completed successfully in under 4 seconds.
- **SC-005**: 95% of users can successfully navigate to and view an owner's details page without errors.
- **SC-006**: The system prevents the creation of duplicate pet names for the same owner, providing immediate feedback.
